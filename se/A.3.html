A.3 平行宇宙與分支沙盒：無風險的商業策略試錯

學完本節，你能夠：

  1. 用分支（branch）隔離試算中的修改，讓主線 main 的現行報價不受影響。
  2. 用 git stash 暫時收起改到一半的修改，並說出它「不會」收哪些東西。
  3. 區分「快轉合併」與「合併提交」兩種結果，並在合併前檢查試算是否守住毛利底線。

壹、開場情境：黑五促銷，要不要全面打九折？

📌 以下為教學情境（依實務改編）。

業務主管想在黑色星期五對 B、C 兩款鍵盤打九折。財務擔心毛利，要求先試算再決定。

問題是：報價表 quotes.csv 是業務每天在用的現行版本。如果直接把價格改成九折去試算，試算期間任何人拿這份表報價，就會用促銷價賣出。

本節要解決的問題： 能不能在不動到現行報價的情況下，複製一份完全相同的環境去試算，試算通過才正式採用，不通過就整份丟掉？

貳、分支是什麼

分支（branch） 是從某個存檔點分岔出去的一條平行紀錄。你在分支上做的修改與存檔，不會出現在 main 上，直到你決定合併。

概念 白話說明
main 主線，代表「現行有效」的版本
分支 從 main 某一點複製出去的沙盒，名稱自取，如 promo/black-friday
HEAD 「你現在站在哪條分支上」的標記
切換分支 工作目錄的檔案會立刻變成那條分支的內容
合併（merge） 把分支上的修改納入 main

Git 的分支非常輕量：它本質上只是一個記錄「最新存檔編號」的小檔案，不會把整個資料夾複製一份。所以開分支幾乎不花時間與空間，開分支的成本遠低於改壞主線的成本。

本節結束時，版本歷史會長這樣：

gitGraph commit id: "建立報價資料庫" commit id: "A款重報 €112" branch promo/black-friday checkout promo/black-friday commit id: "B、C款打九折" commit id: "取消B款折扣" checkout main commit id: "新增報價有效期限" merge promo/black-friday

參、把規則寫下來：什麼時候該開分支？

主管說的話 需要追問的問題 寫成規格
「先試算看看」 試算期間現行報價能不能動？ 不能。所有試算在分支上做，main 只放核准過的版本
「通過再上線」 什麼叫通過？ 分支上每一款產品毛利率都 ≥ 15%（MIN_MARGIN）
「不行就算了」 試算紀錄要留嗎？ 不合併；分支可刪除，或保留作為決策紀錄
（主管沒說） 分支怎麼命名？ 類型/主題，如 promo/black-friday、sales/de-bulk

肆、動手做

1. 開分支並切換過去

對代理說：「從 main 開一個叫 promo/black-friday 的分支，並切換過去。」

git switch -c promo/black-friday

Switched to a new branch 'promo/black-friday'

git switch -c 是「建立並切換」。較舊的教材會寫 git checkout -b promo/black-friday，效果相同。

2. 在分支上試算並存檔

把 B 款改成 135、C 款改成 180（九折），存檔：

git commit -am "feat(promo): 黑五試算 B、C 款打九折"

-a 會自動把「已經被 Git 追蹤的檔案」的修改加入暫存區，省去 git add；新檔案不會被自動加入。

用第 1.1 節的公式（匯率 31.5）檢查毛利率：

產品 成本 原價 → 九折 毛利率 判定
B 款 NT$ 3,900 €150 → €135 17.5% → 8.3% 🛑 低於 15%
C 款 NT$ 4,800 €200 → €180 23.8% → 15.3% ✅ 勉強通過

結論：B 款不能打九折。在分支上把 B 款改回 150，再存一次檔：

git commit -am "fix(promo): B款毛利跌破底線，取消折扣"

這時切回 main 看看：

git switch main

main 上的 B 款仍是 150、C 款仍是 200。試算期間，業務用到的一直是現行報價。

3. 改到一半要切換：git stash

你在分支上又開始改新的試算，改到一半，主管要你立刻調出現行報價。你嘗試切回 main：

error: Your local changes to the following files would be overwritten by checkout:
    quotes.csv
Please commit your changes or stash them before you switch branches.
Aborting

Git 拒絕切換，因為你未存檔的修改會被 main 的版本蓋掉。半成品又不想 commit，這時用 stash（暫存收納）：

對代理說：「把目前沒改完的修改先收起來，然後切回 main。」

git stash push -m "WIP: 黑五草稿"
git switch main

處理完主管的事，回到分支把半成品拿出來：

git switch promo/black-friday
git stash pop

⚠️ stash 預設不收「未追蹤的新檔案」

你新建、還沒 git add 過的檔案（例如 promo_draft.txt）不會被收起來，切換分支時會一起跟過去。要連新檔案一起收，用 git stash push -u。

4. 合併回主線

財務核准「只有 C 款打九折」。在這段期間，同事也在 main 上新增了 terms.md（報價有效期限）。

對代理說：「切回 main，把 promo/black-friday 合併進來。」

git switch main
git merge --no-edit promo/black-friday

💡 這次是合併提交，不加 --no-edit 的話，Git 會打開文字編輯器讓你填寫合併訊息；加上後直接沿用預設訊息。

Merge made by the 'ort' strategy.
 quotes.csv | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)

git log --oneline --graph 會顯示兩條線匯合：

*   4d0ed1a Merge branch 'promo/black-friday'
|\
| * 41936f7 fix(promo): B款毛利跌破底線，取消折扣
| * cdaca5a feat(promo): 黑五試算 B、C 款打九折
* | 0ff4114 docs: 新增報價有效期限條款
|/
* 89dcec1 fix(quote): A款依 1.1 建議重報 €112

合併有兩種結果：

情況 Git 的做法 輸出關鍵字
開分支後 main 沒有新存檔 直接把 main 往前移到分支最新點，不產生新 commit Fast-forward
開分支後 main 也有新存檔（本例） 產生一個有兩個「上一版」的合併提交 Merge made by the 'ort' strategy

最後刪除已合併的分支（紀錄已在 main 裡，不會遺失）：

git branch -d promo/black-friday

陸、回到情境與小結

黑五試算全程在分支上進行，main 的現行報價一刻都沒有被動到；試算發現 B 款會跌到 8.3%，在合併前就被攔下，最後只有 C 款的九折進入 main。

限制 後果 在哪一節解決
兩條分支改到同一行 合併時 Git 無法自動決定 A.4 衝突處理
合併前沒有人複核 試算人自己合併，等於自己批准自己 A.6 Pull Request
毛利檢查仍靠人工計算 試算者忘了算，就可能合併不合格的報價 合併前執行 1.1 的 checkQuotes()；第 5 章的測試

本節小結

  1. 分支是低成本的沙盒：試算在分支上做，main 只放核准過的版本。
  2. git switch -c 開分支，git merge 合併；合併結果分成快轉與合併提交兩種。
  3. git stash 能暫時收起未存檔的修改，但預設不收未追蹤的新檔案。
  4. 合併前用商業規則（毛利 ≥ 15%）驗收，分支才真正發揮「試錯」的價值。

柒、練習

  1. 改數字（5 分鐘）：如果 C 款改打 85 折（€170），毛利率是多少？能合併嗎？（提示：毛利率 = 1 − 4,800 ÷ (170 × 31.5)。）
  2. 開分支（20 分鐘）：開一個 promo/spring 分支，把 A 款降到 €105，存檔後算毛利率；切回 main 確認 A 款仍是 €112；最後決定要合併還是刪除分支，並用 commit 說明或一段文字記下理由。
  3. 管理反思（討論）：有人主張「試算失敗的分支應該保留，不要刪」。請從決策紀錄、版本庫整潔、日後誤用三個角度討論，並提出你的分支保留規則。
